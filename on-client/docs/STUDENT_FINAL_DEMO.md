## 2. 3분 개발 시연 순서

[한 장 실행 안내](STUDENT_DAILY_START.md)대로 Node24.19.0에서 `node student/start-daily.mjs`로 켠다.

1. 첫 화면: CPU/메모리/디스크는 「조회 전」, SDP는 「확인 불가」임을 설명한다. 자동 수집을 한 것으로 말하지 않는다.
2. 「내 PC 상태 다시 조회」: 대기→실측·단위·측정 시각·출처를 확인한다. 다시 눌러 이전 실측과 변화량을 보여 준다. 값이 높거나 낮다는 이유로 안전/위험 판정을 하지 않는다.
3. 「연결과 기록 다시 조회」: Windows에서는 구성과 세 방화벽 프로필, 두 로그의 기간/건수를 보여 준다. Mac은 Windows 항목이 확인 불가임을 그대로 보여 준다. Up/설정켜짐/오류건수가 각각 인터넷성공·안전·공격을뜻하지않는다고설명한다.
4. SDP카드와 상단 기존서버 연결상태를 구분한다. 계정·기기·세션과 이전기능은 펼쳐서 확인할 수 있다.
5. 실패 근거 화면을 열어 디스크만 확인불가이며 가짜값이 없고 다음행동이 있는지 보여 준다. 이는 시험 전용 실패 재현이며 현재 PC 디스크가 실제 고장났다는 설명이 아니다.
6. 한계를 보여 주고 끝낸다. 공식 설치/바로가기 시연이 준비됐다고 말하지 않는다.

이 순서로 Mac 브라우저에서09:53~09:54 다시 실행했다. CPU25.79→30.55%, 메모리47.60→47.84GiB, 디스크494.20→494.16GiB와각시각/변화량이표시됐고, 연결조회/Windows미지원/SDP확인불가가같이표시됐다. 당시 관측이며현재값이나벤치마크가아니다.

## 4. 값의 종류

- 실제 조회: 앱이 실행 중인 OS의 자원과 구성, Windows 설정/로그집계. 항목마다출처·조회시각을표시한다.
- 설명용 예시: 이번 개발 실행은 `--demo`를쓰지않는다. 기존demo모드는별도시작한학습자료이며운영결과로전환하지않는다.
- 미연결: 기존기반서버는disconnected/ENGINE_NOT_CONNECTED. 이사실을SDP서버실제연결의관측으로대체하지않는다.

## 5. 소스·패키지 일치와 재현

- 개발 기능 검증 소스: `9025d5e` 저장점. 이후문서기록커밋은실행기능을변경하지않는다. 과거22단계의`STUDENT_RELEASE_SOURCE.json`은역사고정본이며이번소스일치증빙으로재사용하지않는다.
- 공식manifest의 `source.git.head`: **미확인**. manifest가생성되지않았다.
- 공식 패키지 경로·INSTALL.md·승인host바로가기·소스/패키지동일커밋: **미확인/미완료**.
- 원인: `package-app`명령없음. 실제첫오류 `Missing script: "package-app"`. PROVIDED_RUNTIME_NOT_INSTALLED를관측한것은아니다.

- 이번에 확인한 것은 소스 개발 실행이다. Node를설치패키지나승인host대신사용했다고표현하지않는다.
