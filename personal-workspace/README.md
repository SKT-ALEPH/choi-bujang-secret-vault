# 케셰브 개인 운영

본인 ChatGPT 연결과 NetBird를 사용해 Mac 앱과 Windows 업무 서버를 하나의 동선으로 연결한다. **공식 ALEPH 계정·수업용 SDP·CLCO를 사칭하지 않는 개인 운영 모드**다. 원래 과제용 소스, Vercel 자료실과 Supabase 데이터는 변경하지 않는다.

## 실제로 하는 일

| 화면 | 원천과 동작 |
|---|---|
| 보호 현황 | 이 앱에서 이미 승인한 SIWC SDK 계정 상태, NetBird CLI, 서명된 Windows 업무 서버의 기기 등록·세션·권한 상태 |
| PC 상태 | Mac과 Windows의 실제 CPU/메모리/디스크·네트워크 구성, Windows 일반 사용자 권한의 방화벽 프로필·System/Application 건수 |
| 업무 앱 | Windows SQLite의 본인 자료 저장·수정·버전 충돌 검사·보관·복구. 자료실 허용/거부, 보관함의 5분 열기 확인(challenge), 원천 불가 시 unknown |
| 보안 기록 | Windows 업무 서버가 실제로 저장한 본인 접속·자료 작업·정책 변경, 종류/앱/상태 필터·근거 상세 |
| 개인 XDR 경보 | 같은 본인 기기의 인가 거부가 60초 안에 5회 쌓일 때 경보 한 건 저장. 알림이며 공격 확정이나 자동 차단이 아님 |
| 조치 | 서버가 지원하는 본인 기기의 **개인 업무 공간 접근 철회** 또는 **개인 업무 공간 이용 권한 회수**. 준비→사람 확인→SQLite 트랜잭션의 실제 효과→현재 결과 재조회. 재전송은 같은 영수증, 재시작 후에도 영수증 조회 가능 |
| 접근 복구 | 현재 계정과 신뢰된 기기 서명을 확인한 뒤 본인이 명시적으로 앱 범위의 권한·세션을 복구. 기존 자료 유지 |
| AI | 기존 Keshev Personal AI SDK·OS 키체인·프로필 관리·모델 조회/선택·실제 응답·취소를 재사용. 선택한 사건의 최소 근거 미리보기·동의·digest 대조 후 전송, 완료 뒤 계정/사건/현재 정책 재검증 |
| AI 도움받기 | 사용자가 검토한 수동 입력 또는 비밀 없는 진단 요약 설명. 자동 요청·자동 집행 없음 |
| 취약점·도움정보 | 루트 프로젝트에 설치된 공개 승인 패키지 4종과 정확한 버전을 OSV에 대조. 시각·출처·lock 해시·부분 실패 보존. 비밀 없는 연결 진단을 명시적으로 복사 |

`device:revoke`, `grant:remove`의 범위는 **이 개인 업무 서버**다. NetBird 등록 자체나 OS·기존 Vercel 자료실 계정을 회수하지 않는다. 기기 등록/NetBird 연결이 PC 보안 기준 충족을 뜻하지 않으므로 compliance는 unknown을 유지한다.

기존 Wazuh 여섯 탐지기는 원래 프로젝트에 보존했다. 이번 개인 모드의 경보 원천은 위 업무 서버의 실제 인가 기록이다. PC 전체의 Wazuh 수집, 프로세스/랜섬웨어/반출 실시간 감시나 운영 반의 권한 연결을 설치했다고 주장하지 않는다. 보관함 열기 확인은 실수를 줄이는 5분 확인이며 다중요소 인증이 아니다.

## 실행

현재 검증 기준은 Apple Silicon Mac + Parallels Windows 11 ARM64, 공식 Node.js **24.19.0**, NetBird **0.81.4**다. 두 기기는 같은 NetBird 계정에 등록되어 있어야 한다. 현재 구성은 `keshev-mac-client → keshev-windows-resource / 단방향 TCP 54123`, 기본 전체 허용은 비활성이다. 이 시작기는 계정 등록·새 NetBird 권한 부여·OS 보안 해제를 대신하지 않는다.

Mac에서 저장소 루트(`vault`)를 연 뒤:

```sh
node personal-workspace/start.mjs
```

Node의 전역 버전이 다르면 검증한 portable Node 실행 파일의 전체 경로로 같은 명령을 실행한다. 시작기는 다음을 수행한다.

1. Mac NetBird 연결과 지정된 `Windows 11` VM을 확인한다. 등록된 VM이 꺼졌으면 실행한다. VM의 사용자 로그인과 Parallels Tools·Mac Home 공유는 준비되어 있어야 한다.
2. 기존 앱 전용 키체인 암호화로 개인 업무 기기키를 불러오거나 최초 생성한다. **공개키만** Windows로 전달한다. OAuth 자격과 개인키는 옮기지 않는다.
3. Windows 일반 사용자로 `%USERPROFILE%\KeshevRuntime\node-v24.19.0-win-arm64\node.exe`를 실행한다. 지정한 학생 OS 읽기 모듈과 업무 서버 코드만 개인 런타임 폴더로 복사한다.
4. 자신이 띄운 Windows 업무 서버만 교체한다. 포트의 소유가 확인되지 않으면 중단하고 다른 프로그램을 종료하지 않는다.
5. 실제 Windows 사설 health 응답을 확인한 후 Mac 앱을 시작한다.

**http://127.0.0.1:5189/** 를 연다. `localhost` 대신 이 주소를 쓴다. 이미 같은 개인 앱이 실행 중이면 기존 앱 주소를 안내한다. 다른 프로그램이 포트를 쓰면 그 프로그램을 임의 종료하지 않는다. 이전 학생 개발 앱을 직접 켰다면 해당 창에서 Ctrl+C로 끈 뒤 다시 실행한다.

Mac 앱 종료는 실행 창의 Ctrl+C다. Windows 업무 서버와 NetBird 서비스는 계속 실행되며, 앱을 다시 켜면 원래 개인 자료·경보·영수증을 이어 읽는다. Windows 재부팅 후에도 같은 시작 명령으로 다시 켠다. setup.exe, 시스템 자동 시작 작업, OS 방화벽 해제, ExecutionPolicy 변경은 추가하지 않았다.

`--adopt-pid=<숫자>`는 본 작업에서 만든 과거 개발 서버를 새 개인 런타임으로 **최초 이전할 때만** 사용한 운영자 옵션이다. 평소 실행에는 필요 없다. 다른 프로세스를 선택해 종료하는 용도가 아니다.

## 처음 화면에서 확인

1. **보호 현황**에서 계정 연결·NetBird 연결·업무 공간의 서버 판정을 확인한다. 필요하면 전체 다시 확인을 누른다.
2. **업무 앱 → 자료실 접근 요청**이 허용되면 새 개인 자료를 저장한다. 수정은 현재 revision을 대조한다. 보관은 soft delete이며 보관함에서 복구할 수 있다.
3. **보관함 접근 요청**이 추가 확인이면 범위를 읽고 확인한다. 확인 전 서버도 보관 자료를 반환하지 않는다.
4. **보안 기록**에서 실제 기록과 근거를 읽는다. AI를 쓰려면 **계정과 AI → 모델 불러오기 → 모델 선택**, 기록의 전송 미리보기/동의 후 설명을 요청한다.
5. 조치는 기록에서 준비해 실제 대상과 기한을 읽은 뒤 별도 확인한다. AI 설명 버튼은 조치 요청을 보내지 않는다.
6. 회수 뒤 실제 자료 요청이 거부되는지 확인한다. 본인 복구는 보호 현황에서 명시적으로 수행한다. 저장된 조치의 과거 효과와 현재 적용 여부는 다를 수 있다.

## 경계와 저장

- 브라우저는 정확한 Host·Origin·same-origin fetch와 포트별 HttpOnly/SameSite 쿠키로 보호한다. 브라우저가 원격 주소·명령·owner·device·session을 선택할 수 없다.
- 서버는 매 요청 현재 SIWC SDK 프로필을 확인한다. SDK가 검증해 저장한 **이 앱의 로컬 프로필 ID**를 가명화해 Windows의 개인 공간에 결속한다. ALEPH canonical ID나 NetBird 사용자를 임의로 같다고 만들지 않는다. 공유 PC·다중 운영자용 중앙 인증 서버는 아니다.
- Windows는 Mac의 NetBird 출발 주소, 미리 설치한 Ed25519 공개키, 서명된 메서드/경로/시각/body 해시, 영속 nonce 중복 방지를 확인한다. 네트워크 연결만으로 자료 API를 호출할 수 없다.
- Mac 개인 업무키: 사용자 Library의 `Keshev Personal Workspace/agent-key.enc`, OS 키체인 암호화. 기존 SIWC 자격은 `Keshev Personal AI`의 SDK 저장소에 그대로 둔다. 앱 런타임만 읽고 원문을 출력하지 않는다.
- Windows 업무 DB: `%LOCALAPPDATA%\Keshev Personal Workspace\workspace.sqlite`. 새 개인 자료·감사 기록·서버 권한·확인 티켓 해시·영수증을 저장한다. 기존 Supabase 자료를 복사하지 않는다.
- Windows 실행 사본: `%LOCALAPPDATA%\KeshevPersonalWorkspaceRuntime`. Mac `runtime-public/`에는 비밀이 아닌 공개키만 내보내며 Git에서 제외한다.
- 메모 본문은 접속 기록·AI·진단·Git·공개 정적 파일에 넣지 않는다. 모든 노트 쿼리는 owner를 함께 대조한다. 사용자 자료를 원격 보관·과거 DB 복원으로 정리하지 않는다.
- 조치는 준비 당시의 사건/정책 세대에 결속하고 확인을 일회 소비한다. 재시작 뒤 자동 집행하지 않는다. 원천 관측 없이 성공으로 만들지 않고, 복구/다른 정책 변경 뒤에는 과거 succeeded 영수증을 현재 적용으로 표시하지 않는다.
- AI 미리보기에는 과거 관측 상태와 서버에서 다시 읽은 현재 상태를 구분한다. 전송 전 digest, 완료 뒤 계정/사건/정책을 대조한다. AI의 조치 제안은 서버 지원 목록만 수용하며 실행하지 않는다.

## 검증

```sh
node --test test/personal-workspace.test.mjs personal-ai/server.test.mjs
```

시험은 소유자 격리·revision·보관/추가확인·실제 SQLite 효과·반복 거부 경보·영수증/재시작·위조 서명/변조/재전송 거절·브라우저 세션/교차 출처·계정 변경·사건 근거 결속·AI 오류/취소를 확인한다. 모의 SIWC 시험을 실제 OpenAI 응답이라고 보고하지 않는다. 실제 Mac↔Windows, UI, OSV, AI 결과와 한계는 저장소 밖 `artifacts/final-assault-2026-10-26/`의 별도 증빙과 대조한다.

### 2026-10-26 실제 기기 확인

- Mac→NetBird→Windows의 실제 서명 요청과 서버 인가, 자료 추가·수정·보관·추가 확인·복구 및 재시작 후 버전 4 보존을 확인했다.
- 이용 권한 회수와 기기 접근 철회 각각의 원천 효과, 실제 자료 거부, 본인 접근 복구를 확인했다. 재시작 뒤 두 영수증은 과거 효과를 유지하고 현재 정책 변경을 구분했다.
- 실제 인가 거부 5건/60초로 경보 한 건을 생성했다. 보관함 새 기록은 별도 앱 필터로 조회한다. 과거 불변 기록의 앱 표시는 소급 수정하지 않는다.
- 기존 승인 계정에서 실제 모델 7종을 조회하고 **GPT-6-Luna**로 사건 근거 설명·최소 진단 설명·연결 점검의 완료 응답을 받았다. 사건 설명은 과거 거부와 현재 허용을 구분하고 전체 근거 ID를 인용했다. 자동 집행은 없었다.
- 실제 CPU/메모리/디스크·Windows 네트워크/방화벽/기록, OSV 4개 설치 패키지의 시각·출처·버전을 확인했다. 당시 알려진 항목이 없었으며 다른 패키지·PC 전체 안전을 판정한 것은 아니다.
- 업무 서버만 중단했을 때 이전 허용과 자료를 제거하고 연결 실패를 표시했다. PC 조회도 로딩으로 남지 않았다. 같은 시작 명령으로 복구했고 개인 DB와 기존 SDK 계정은 유지했다.
- 375px에서 가로 넘침 없이 네 화면을 확인했고 보이는 버튼의 높이는 44px 이상이었다. 정상 화면 크기로 복구했다.
- 계정 전환·로그아웃·오류·취소·시간 초과의 경계는 격리된 SDK 시험으로도 검증한다. 현재 사용자 계정을 실제 로그아웃하거나 새 승인으로 교체했다고 주장하지 않는다.
