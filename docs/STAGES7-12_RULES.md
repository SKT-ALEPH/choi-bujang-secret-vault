# 7~12단계 문제 제약 RULE

## 공통 사용자 조건
- R-WORK-CONTINUE: 지시된 전체 작업 완료 전 임의 중단 금지. 하위 작업 구현·검증·기록 후 자동 진행하며 부분 완료나 미해결 원인만으로 대화를 종료하지 않는다. 실제 입력/접근 차단은 근거와 필요한 조치를 알리고 독립 작업을 계속한다. 미완료 제출 금지 및 단계100점 순서를 함께 준수한다.
- 단계의 접힌 안내·제작·확인·제출·실패·복구 안내와 필수 계약을 모두 읽은 후 구현한다.
- 모든 요구사항을 구현 위치 및 검증 결과와 대조한다. 실제 연동·설정·검증이 미완료면 제출하지 않는다.
- 실제 심판 100/100점 전 다음 단계 구현을 하지 않는다.
- 작업–하위 작업 트리와 개별 기록을 유지한다. 압축 후 현재 작업 문서를 상기하고, 전체 트리와 최종 end-to-end 검증 전에는 임시 기록을 폐기하지 않는다. 하위 작업 완료 후 자동 진행한다.
- 통제는 플랫폼 전체 요청에 적용되어야 한다는 사용자 요구를 유지한다. 구현·시험·운영 심판 결과를 구분한다.
- 기존 자료·주소·Auth·기기·이전 방어 규칙·고정 이력을 보존한다. 비밀값을 코드·로그·답변·Git에 남기지 않는다.
- 판정기의 18필드 요청/5필드 응답 계약과 원본 로그인 검증 도우미·judgeIssuer를 보존한다. 계약 밖 역할·신원·기기 값을 발명하지 않는다.

## 7단계 평소와 다른 접속
- R-S07-SOURCE: signals.source가 judge_fixture인 가상 사건만 지역/시각/네트워크 근거로 해석. source none은 운영 계약상의 미제공 상태로 명시. 출처 불명·값 누락을 정상값으로 치환하지 않음. 임의 헤더를 신뢰 정보로 승격하지 않음.
- R-S07-COMBINATION: 낯선 네트워크·이른/늦은 시각·최근 대량행동 복합일 때 step_up_required, 지역 하나만 영구차단 금지. 현재 fixture는 hour3/networkunusual/risk_signal20건 age60이며 정상은 hour14/usual/사건없음이다. 수치 정책은 시험의 구현 선택으로 설명.
- R-S07-STEPUP: 엔진이 검증한 stepUp.verified===true와 유효 age0~900일 때 재판정. 미확인 상태는 추가확인, 조건 해소 또는 검증 후 허용. 직접 토큰을읽거나 가짜확인값을웹요청에추가하지않음.
- R-S07-VERIFY: npm run fixture:7과 decider:test 정상/복합/재확인·기기거부 확인. 제공 엔진의 실제 재로그인 계약이 준비된 환경에서만 실측하며 그렇지 않은 일반브라우저의 재로그인 차단·허용은 미실행 기록. 새 설치 명령 금지.

## 8단계 — 원문에서 다시 작성한 조건

2026-10-13 사용자 맥락 초기화 요청 후 현재 문제 창의 모든 접힌 안내를 다시 읽었다. 이전 8단계 원인 추정 및 자체 추가 제약은 적용하지 않는다. 현재 작업 기록은 저장소 상위의 STAGE8-WORK.md이다.

- R-S08-RESOURCE: 메모와 강사 공지를 서버가 요청마다 구별할 수 있는 서로 다른 자원 ID로 표시한다. 기존 자료와 주소를 보존하며 화면 메뉴를 변경하지 않는다.
- R-S08-DECIDER: 판정기에 자기 메모 읽기·수정 및 강사 공지 수정의 구역 규칙을 넣는다. 엔진이 확인한 사용자·기기·메서드·정확한 경로를 사용하며 알 수 없는 경로를 거부한다. 이전 규칙을 유지한다.
- R-S08-PATH: 쿼리로 기능을 고르지 않고 자료 ID만 고른다. :id와 같은 깊이에 export 같은 기능 경로를 두지 않는다.
- R-S08-EXPECTED: A의 자기 메모는 허용하고, B의 A 메모 접근과 일반 학생의 공지 수정은 거부한다.
- R-S08-API: 자료 API에서도 검증된 사용자와 저장된 소유자·강사 권한을 다시 대조한다. 화면 메뉴나 요청 본문의 role을 믿지 않는다. 짧은 거부 사유를 남기며 직접 API 요청에서도 다른 구역 자료가 나오지 않아야 한다. 본인 정상 요청은 유지한다.
- R-S08-SUBMIT: 완전 구현·검증 후 8단계 저장점 커밋과 npm run bundle을 실행한다. 첫 오류를 근거로 수정한다.
- R-S08-REPAIR: 기대 결과와 실제 화면/첫 오류를 구분하고 비밀값을 제거한다. 원인 후보 2~3개 중 가장 가능성 높은 하나를 최소 수정하고 다른 기능을 보존한다. 원인 추정은 문제 제약으로 승격하지 않는다.
- R-S08-ROLLBACK: 되돌리기는 git 상태·차이를 통해 단계 변경과 다른 변경을 구분하고 사라질 내용을 보여 준 뒤 확인받아 실행한다. 다른 변경·DB 자료를 보존하며 reset --hard를 사용하지 않는다.
