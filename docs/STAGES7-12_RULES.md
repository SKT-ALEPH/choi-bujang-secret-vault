# 7~12단계 문제 제약 RULE

2026-10-13 실제 단계 안내를 읽은 뒤 해당 절을 추가한다. 운영 심판과 로컬 연습을 구분한다. 실제 연동이 필수인 조건은 구현·설정·검증 전 제출 금지. 안내가 명시적으로 제공 계약 부재 시 가상 시험과 미실행 기록을 허용한 항목은 그 범위를 따르며 임의의 운영 기능을 지어내지 않는다.

- R-S312-CONTRACT: DECIDER_REQUEST.md의18필드와 응답5필드, DETECT_EVENTS.md 사건 모양 준수. 엔진 검증값만 사용. 브라우저 위조 사용자/역할/위치/기기 필드 신뢰 금지.
- R-S312-PRESERVE: 기존 Auth·소유자·직접DB 차단·기기 규칙·XDR 유지. judgeIssuer 불변. 기존 메모·계정·cold 고정본 보존.
- R-S312-SECRET: 새 개인키/인증서/토큰/개인정보를 임의 생성·기록·공유하지 않음. 필요한 비밀값은 공식 입력란, 채팅금지.
- R-S312-WORK: 작업 트리와 단위 기록 유지, 압축 후 재상기, 다음 단위 자동진행. 전체 트리+최종end-to-end 통과 전 임시 문서 폐기 금지.
- R-S312-SAVE: 단계별 README·step·실제 규칙 갱신, 비밀검사→저장점→실배포 commit일치→bundle→심판 제출·판정. 가상/실제 점검 구분.

## 7단계 평소와 다른 접속
- R-S07-SOURCE: signals.source가 judge_fixture인 가상 사건만 지역/시각/네트워크 근거로 해석. source none은 운영 계약상의 미제공 상태로 명시. 출처 불명·값 누락을 정상값으로 치환하지 않음. 임의 헤더를 신뢰 정보로 승격하지 않음.
- R-S07-COMBINATION: 낯선 네트워크·이른/늦은 시각·최근 대량행동 복합일 때 step_up_required, 지역 하나만 영구차단 금지. 현재 fixture는 hour3/networkunusual/risk_signal20건 age60이며 정상은 hour14/usual/사건없음이다. 수치 정책은 시험의 구현 선택으로 설명.
- R-S07-STEPUP: 엔진이 검증한 stepUp.verified===true와 유효 age0~900일 때 재판정. 미확인 상태는 추가확인, 조건 해소 또는 검증 후 허용. 직접 토큰을읽거나 가짜확인값을웹요청에추가하지않음.
- R-S07-VERIFY: npm run fixture:7과 decider:test 정상/복합/재확인·기기거부 확인. 제공 엔진의 실제 재로그인 계약이 준비된 환경에서만 실측하며 그렇지 않은 일반브라우저의 재로그인 차단·허용은 미실행 기록. 새 설치 명령 금지.
