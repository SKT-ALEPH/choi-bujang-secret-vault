# XDR-01 문제 제약 RULE

사용자 지시: 반복 실패 원인을 분류하고, 문제 제약을 지속 규칙으로 지정한다.
과제 근거: ALEPH 보너스 XDR-01의 제작 1~5 및 제출 전 확인 안내.
이 문서는 임시 작업 과정이 아니라 다음 수정에도 적용하는 영구 제약이다.

## 실패 분류

| 분류 | 실제로 놓친 것 | 확인 근거 / 확정 범위 |
|---|---|---|
| 완료 판단 | Jev 실제 연동·실제 거부 경로가 미완료인데 초기 제출 | 진행 기록과 사용자 지적. 인터페이스·가상 응답은 실제 연결 완료가 아니다. |
| 입력 계약 | 읽기 모듈의 다섯 항목 출력을 판단 모듈이 원본 Wazuh 구조로만 처리 | 원본/추출 동등성 시험에서 재현·수정. 이것만이 초기 심판 실패 원인이었다고 단정하지 않는다. |
| 실행 환경 | 판단 코드가 파일·Node import·JSON import·process에 의존 | c445e10은 차단 부족 0점, standalone 4f0ae5f는 명확한 차단 통과·30점. 각 의존성 중 어느 하나가 심판 내부에서 실패했는지는 비공개이다. |
| 검증 환경 | 격리 시험에 TextEncoder·AbortController·타이머를 주입하여 기능 부재를 숨김 | 완전히 빈 VM에서 경보 9건의 ReferenceError 재현: 차단10/알림0/기록18. 심판의 알림/기록 불일치와 일치하는 유형이며 내부 건수는 공개되지 않았다. |
| 범위 해석 | 미래 반 ZTNA 엔진 설치를 지금 과제의 필수 조건으로 추가 | 현재 과제 안내와 개방 단계 재확인 후 기존 자료실의 HTTP 접근 통제 연결로 구현. 운영 PC·반 엔진 설치를 완료했다고 주장하지 않는다. |

## 반드시 지킬 RULE

1. **R-X01-COMPLETE** — 실제 Jev 연동, 실제 자료실 차단 연결, 필요한 DB 권한, 실제 배포 동작을 모두 검증한 뒤 제출한다. 대체 경로·가상 응답·연결 인터페이스만으로 완료 처리하지 않는다. 심판 접수·부분 점수는 과제 완료가 아니다.
2. **R-X01-CONTRACT** — `decide(alert)`는 원본 Wazuh 입력과 읽기 모듈의 다섯 항목 입력을 모두 처리한다. 형식을 섞어 부족한 원본을 보충하지 않는다. 같은 근거는 같은 판정이 나와야 한다. 반환은 유한한 0~1 확신도, block/alert/record 중 행동 하나, 근거 패턴의 한 줄 이유이다.
3. **R-X01-CLASSIFY** — 명확한 공격은 차단, 애매한 시도는 알림, 정상 활동은 기록한다. 확신도 0.85 이상 block, 0.5 이상 alert, 미만 record. Jev 실패·무응답·형식 오류는 alert이며 예외로 실행기를 중단하거나 record로 떨어뜨리지 않는다. 오류는 자체적으로 차단 근거가 아니다.
4. **R-X01-ISOLATED** — 심판용 판단 모듈은 파일·Node 모듈·JSON import·process·fetch·TextEncoder·AbortController·타이머가 없는 ECMAScript 격리 환경에서도 원본 경보 재생을 끝낸다. 시험 환경에 편의 기능을 주입해 이 제약을 숨기지 않는다. 실제 서버의 Jev 요청에는 제한시간과 취소를 유지한다. 생성된 모듈을 커밋하고 원본 변경 뒤 다시 생성한다.
5. **R-X01-EVIDENCE** — 경보 ID, 배열 순서, 시험 정답을 판단 알고리즘에 넣지 않는다. 실패 빈도·계정 수·시간 창·반복 패턴을 판단한다. ID/순서를 바꾼 재생도 같은 결과를 낸다. 공식 fixture는 변경하지 않는다. 정상 이벤트의 차단으로 점수를 맞추지 않는다.
6. **R-X01-ENFORCE** — 실제 차단은 서버가 신뢰하는 출발 주소만 이용한다. 클라이언트 본문·임의 IP 헤더를 믿지 않는다. 규칙에는 만료 시각과 근거 경보 ID를 보관하고 15분 만료 시 차단을 해제한다. 기존 deny/step_up, 로그인 검증, 사용자 소유자 검사는 보존한다. 요청 계약에 임의 IP 필드를 추가하지 않는다.
7. **R-X01-PRIVACY** — Jev에는 허용한 수치·불리언만 보낸다. 원본 주소·계정·비밀번호·토큰·키·사용자 메모를 보내거나 공개 파일·로그·Git·제출 묶음에 남기지 않는다. 규칙·경보 저장소는 서버 전용이며 공개 경로에서 읽히지 않아야 한다.
8. **R-X01-DEPLOY** — 제출 직전에 저장소 커밋과 실제 배포 신원이 일치하고, 실제 비로그인 요청 거부와 정상 기능이 유지됨을 확인한다. 로컬 시험, 실제 HTTP 검증, 실제 Jev 응답, 심판 판정을 구분해 기록한다. 만료 시각을 앞당긴 시험을 15분 동안 기다린 시험으로 표현하지 않는다.
9. **R-X01-REPAIR** — 실패하면 심판 코드·해당 커밋·첫 재현 오류를 기록한다. 확정 원인과 추정을 구분하고, 수정 뒤 해당 실패 환경을 직접 시험한다. 과제에 없는 외부 설치를 임의의 필수 조건으로 만들어 작업을 멈추지 않는다. 재현된 미해결 오류가 있으면 재제출하지 않는다.

## 현재 검증 방법

- `npm run xdr:build`: 판단 원본에서 독립 `decide.mjs` 생성.
- `node --experimental-vm-modules --test test/xdr-portable.test.mjs`: 완전히 빈 VM, 원본/추출 동등성, Unicode 해시·IPv6 확인.
- `node --test test/brute-force.test.mjs test/xdr-live.test.mjs`: 오분류·중복·만료·Jev 실패·신뢰 주소·HTTP 차단 확인.
- `npm run xdr:run -- brute-force`: 공식 경보 재생과 알림·규칙 저장 확인.
- 실제 연동·배포의 증빙은 비밀값을 제외한 별도 artifacts에 보관한다. 시험 통과를 심판 통과로 대신 보고하지 않는다.
