# XDR-01 운영 연결에 필요한 계약

현재 구현 상태: 실제 TypeSafe Jev API 호출 검증 완료. 운영 반 엔진의 차단 연결은 미완료.
완전 구현과 실제 연결 검증 전에는 과제를 다시 제출하지 않는다.

학생 시작 틀의 `docs/DECIDER_REQUEST.md`는 요청을18개 필드로 제한하며 출발 IP를
포함하지 않는다. 새 거부 사유도 운영 등록부의 허용 코드로 등록해야 한다.
브라우저가 제공한 IP 또는 가상 주소를 실제 출발 주소처럼 사용하지 않는다.

운영자는 `src/xdr-decider.mjs`의 `connectXdrDecider`를 엔진의 학생 판정 호출 경로에
연결하고 다음 네 항목을 제공해야 한다. 기존 판정 규칙은 변경하지 않는다.

| 연결 항목 | 필요한 동작 |
|---|---|
| `getTrustedSource(requestId)` | 엔진이 실제 요청에서 확인한 주소를 서버 내부에서 조회한다. 클라이언트 본문·시험 주소를 대입하지 않는다. |
| `getRules()` | 신뢰된 경보 처리기가 만든 차단 후보 저장소를 읽는다. 운영 경보의 시각·주소·확신도·근거 ID·만료를 유지한다. |
| `denyReasonCode` | 운영 측에 등록된 XDR 거부 사유 코드다. |
| `allowedReasonCodes` | 같은 정책 버전의 운영 등록부가 실제로 허용하는 코드 목록이다. 학생이 임의로 허용 목록을 만들어 운영 목록인 것처럼 보고하지 않는다. |

기존 결과 deny/step_up는 그대로 반환한다. 기존 결과 allow일 때만 활성 주소 규칙을
추가 검사한다. 만료된 후보는 차단하지 않는다. 원본 요청 필드와 응답5필드는 유지한다.

완료 증빙에는 운영 요청에서 받은 requestId의 가명 지문, 적용된 규칙 ID,
등록 사유 코드, 차단·정상 통과·만료 후 복귀 결과가 필요하다. 실제 사용자 IP,
계정·비밀번호·토큰·기기 개인키·원본 로그를 증빙이나 공개 저장소에 남기지 않는다.

현재 공식 시작 틀과 ALEPH Workbench 설치 안내에는 위 운영 연결을 학생이
설정하는 절차나 주소 조회 API가 제공되지 않았다. 이 계약의 운영 측 구현·등록과
접속 경로 연결을 확인해야 남은 통합 검증을 진행할 수 있다.
