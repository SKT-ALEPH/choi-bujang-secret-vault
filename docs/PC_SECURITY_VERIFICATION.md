실제 데이터는 자체 메모를 추가로 전송하지 않고 생성한 고정 바이트만 두 사설 기기 사이에서 보냈다. 인터넷 수신지 업로드나 암호화 내용 검사는 하지 않았다. PC 관측을 Supabase 계정의 행동으로 결속하지 않으며 새 PC 정보의 외부 AI 전송도 수행하지 않았다.

Mac은 표본 방식이라 짧은 연결이 누락될 수 있고 이미 열린 연결의 강제 종료를 보장하지 않는다. 새 연결 차단을 검증했다. 기본 FIM 지정 경로 밖의 모든 파일·모든 악성 행위·DLP·전원 재부팅까지 검증했다는 뜻은 아니다. Wazuh indexer/취약점 탐지 모듈은 구성하지 않았다.

검증 과정의 최초 XML 파서 오류(raw &&), agentd 파일 권한, ETW 초기화 순서, Windows 종료 후 자체 대응 child의 파일 잠금, CIM 프로토콜 표기, Wazuh 종료 시 조기 delete, manager 초기화 재실행 오류를 각각 재현해 수정했다. 실패 시험을 최종 성공 시험으로 섞지 않았다. 당시 단절과 조기 해제 기록은 원래 감사 저장소에 남아 있다.

원문·인증 코드·토큰·키·메일 주소·사용자 파일 내용을 제외한 증빙은 저장소 밖 `artifacts/wazuh-pc-2026-10-26/evidence/`에 있다. 설치·운영·중지 및 복구 범위는 [연결 안내](../pc-security/README.md)를 따른다. 비밀 등록 파일·개인키·원문 Wazuh 로그·시험 수신 파일은 Git에 포함하지 않는다.

후속 정상 업무 통신 검증: Mac에서 실제 ChatGPT 목적지443의 정상 대량 송신이 조건에 걸린 오탐을 발견했다. 목적지를 출력하지 않고 현재 DNS와 대조해 chatgpt.com/ab.chatgpt.com 일치, codex/node_repl 송신을 확인했다. 사용자 관리자 적용으로 기존 OpenAI 서비스4개의 최근 DNS주소·443만 예외로 추가했고, 10:33:10.814Z 자체 차단 해제 및 nativeclear를 확인했다. 양OS에서 DNS4개 최근 확인을 수신한다. 이 예외는 공인 전체·모든443을 허용하는 규칙이 아니며 동일 CDN주소의 다른 서비스/내용을 구분하지 못한다.

정책 보완 뒤 동일 비승인 시험 목적지58443으로 실제 재시험했다. Mac62,001,448bytes/5연결→100121→10:36:42.179Z nativeadd, 같은포트거부·58444허용. 해제기한10:51:42.179Z이다. 보완 코드에서도 10:51:44.125Z 실제 delete 성공·native clear를 확인했다. 이후 같은58443과58444의 실제 재접속을 확인하고 수신기를 정리했다. 기한을 앞당기거나 수동 해제로 대체하지 않았다.

정상 업무 동시 동작: 10:46:51Z 기존 OAuth 모델7개 실조회, 10:49:08Z GPT-6-Luna 고정 진단 문장의 실제 완료 응답을 확인했다. 이 요청에 PC 관측·원문은 넣지 않았다. 같은 시점 기존 자료실의 원래 계정·기기·본인 메모1건 조회도 유지했다. Wazuh 기본 수집에서 Mac sudo 경보1건, Windows 시스템 기록·SCA·실제FIM변경 수신을 원문 없이 확인했다.

Windows 최신 센서/대응 프로그램 해시 일치, native 자체 점검(target/policy/deadline) 통과. Mac 정책의 신뢰 DNS 예외는 실제 소스의 별도 격리 시험으로 승인 도메인·주소·443 제한, 5분 만료, 다른 목적지/포트의 집행 유지까지 검사했다. 자동 시험 총18개 통과이며 전체 저장소의 모든 시험을 새로 통과했다고 확대하지 않는다.
