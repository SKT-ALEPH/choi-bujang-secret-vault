# 별도 소스 폴더에서 통합 앱 재현

2026-10-27 보완 브랜치 **235c87d639b709fc24031fa74811ccdbf8b38a6e**를 원격에서 새로 clone한 `.local/package-rehearsal-20261027`에서 확인했다. 같은 Mac 계정과 이미 설치·등록된 Windows11/NetBird/Wazuh/Supabase를 재사용한 소스 실행 시험이다. 빈 PC 설치나 새 계정 등록을 검증했다고 하지 않는다. setup.exe는 제외한다.

## 안내대로 준비·실행

1. 두 OS의 Node24.19.0·Windows 일반 사용자 로그인·Mac 공유·NetBird 지정 포트 정책을 확인했다. 원래 소스의 `.local` 자격/설치 파일은 clone에 복사하지 않았다.
2. 저장소 루트 `npm ci`, `personal-ai`의 `npm ci`를 실행했다. `on-client`는 별도 npm 설치가 필요 없다. `node scripts/build-public.mjs --local`은 로컬 자료만 준비하며 Vercel의 배포 신원을 만들어 내지 않는다.
3. 루트 `node personal-workspace/start.mjs`로 이미 설치된 소유 Wazuh manager와 Windows 게이트웨이, Mac 앱이 실행됐다. 새 폴더의 추적 소스를 Windows에 배치하고 기존 OS 앱 저장소·키체인·DPAPI·감사 DB를 그대로 사용했다.
4. http://127.0.0.1:5189/ 를 먼저 열거나 새로고침해 이 실행의 로컬 쿠키를 받는다. 이미 열어 둔 자료실의 정상 로그인/기기 서명으로 목록 새로고침을 누른다. 실패 화면에서는 ‘연결 복구 후 자료 다시 조회’를 누른다. 이전 세션 쿠키를 그대로 쓰는 첫 요청은 거부될 수 있으며 새 인증/자료를 복사해 우회하지 않는다. 브라우저 로그인 자체가 만료됐으면 공식 로그인과 기기 승인을 다시 수행한다.
5. Ctrl+C 종료 후 같은 명령으로 다시 실행하고 위 정상 복구·조회 절차를 반복했다. 기존 브라우저 메모리의 정상 자료실 세션은 유효 기간 안에 재사용했다.
