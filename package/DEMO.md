# 시연 절차

현재는 보완 브랜치 검증 중이다. [SELF-CHECK](SELF-CHECK.md)의 미검증 조건이 남으면 제출하지 않는다. 웹 첫 화면은 새 Vercel URL에서, 실제 업무 기능은 등록된 두PC의 http://127.0.0.1:5189/ 에서 시연한다. localhost 주소를 다른 사람의 원격 시연 URL로 제출하지 않는다.

1. 새 Vercel의 첫 화면·배포 신원을 확인한다. 웹 Auth는 기존 Supabase를 사용한다. 개인 비밀번호·키·실제 메모를 캡처하지 않는다.
2. 등록된 Mac 케셰브에서 기존 자료실을 열고 원래 로그인/기기 승인으로 본인 자료를 조회한다. 일반 사용자는 공식 가입·이메일 확인·기기 승인 절차를 따른다. 채점 계정을 임의 생성하거나 이메일 확인을 해제하지 않는다. 직접 공개 API 우회는 인증/망 경계에서 거부돼야 한다.
3. Windows PC 상태를 새로 읽고 작업 관리자의 같은 시각·단위와 비교한다. 전/후 변화, 부분 실패, 다시 조회, 키보드 이동을 보여 준다. 연결/방화벽 설정과 로그 건수는 상태 관측이다.
4. 공식 침해 정보에서 Wazuh 등 구성요소를 조회한다. 버전 출처·NVD/KEV 수신시각·현재 페이지 범위·KEV 여부와 수동 검토를 확인한다. 두 번째 조회는 실제 캐시 시각이 유지돼야 한다.
5. 서버 AI 검증의 고정 가상 수치를 한 번 전송한다. 실제 모델 결과와 남은 횟수를 읽고 한도에서429를 확인한다. 기존 개인 OAuth 설명은 별도 실제 사건의 최소 근거를 읽는 기능이다.
6. 실제 보안 기록의 근거·규칙을 열고 지원 Agent 조치의 사람 확인→원천 효과→복구를 보여 준다. 이전900초 OS 차단 실측은 [PC 검증표](../docs/PC_SECURITY_VERIFICATION.md)로 확인한다. 새 위험 송신이나 실제 자료 유출을 시연용으로 실행하지 않는다.
7. Ctrl+C로 앱을 닫고 같은 명령으로 재시작한다. 기존 사용자 자료·감사·권한과 DB 호출 한도/캐시가 유지되는지 확인한다. OS 서비스는 별도로 작동한다.

실제 캡처는 `self-check/`의 SELF-CHECK 링크를 따른다. 현재 DB 스키마/권한 확인: [schema.png](self-check/schema.png). P3·P5·P7 캡처는 실측표에 연결했다. P4 실제 성공 응답은 화면 추출 텍스트이며,429 화면과 재시작 후 한도 보존을 확인했다. 최종 접수 커밋은 별도로 대조한다. Windows 실측은 [대조 기록](WINDOWS-COMPARISON.md)을 따른다. 캡처를 만들기 위해 가상 성공 화면을 합성하지 않는다.
